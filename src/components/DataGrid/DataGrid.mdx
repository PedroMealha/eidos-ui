# DataGrid

A feature-rich, spreadsheet-like grid for editing structured data inline. Columns are typed (`text`, `number`, `select`, `checkbox`, `readonly`, `actions`), and the grid supports sorting, filtering, pagination, row selection, drag-and-drop reordering, column pinning, per-cell validation, a row-actions menu, and a responsive card view for narrow containers - all opt-in via props.

> **Note**: `DataGrid` is generic over your row type (`T extends Record<string, unknown>`). Pass the type parameter explicitly - e.g. `<DataGrid<Person> … />` - to get full type safety on `columns`, `onChange`, and callbacks.

## Usage

```tsx
import { DataGrid } from 'eidos-ui';
import type { DataGridColumn } from 'eidos-ui';

interface Person extends Record<string, unknown> {
  id: number;
  name: string;
  role: string;
}

const columns: DataGridColumn<Person>[] = [
  { key: 'id', header: 'ID', type: 'readonly', width: 60 },
  { key: 'name', header: 'Name', type: 'text', minWidth: 160, required: true },
  {
    key: 'role',
    header: 'Role',
    type: 'select',
    width: 130,
    options: [
      { value: 'lead', label: 'Lead' },
      { value: 'senior', label: 'Senior' },
    ],
  },
];

function TeamTable() {
  const [data, setData] = useState<Person[]>([{ id: 1, name: 'Alice', role: 'lead' }]);

  return <DataGrid<Person> columns={columns} data={data} rowKey="id" onChange={setData} />;
}
```

## With filtering

Filterable fields live in their own dedicated `filterConfig` array - `{ key, label, filterType, filterOptions, dateFilterMode }` - kept separate from `columns` so every filterable field is visible in one place, instead of scattered across each column's own definition. `key` doesn't need to match a `columns` entry either - you can filter on any row-data field, including ones you don't render as a column.

Pass `filterConfig` alongside `showFilters={true}` to show the filter-panel toggle in the toolbar. Without `onFiltersChange` the grid filters client-side.

For `filterType: 'date'` fields, `dateFilterMode` (`'single' | 'multiple' | 'range'`, same shape as `TableColumn`) controls which date-picker mode the filter dropdown uses - it defaults to `'single'` if omitted.

## With pagination

Pass `showPagination={true}` and a `pageSize` to paginate client-side. Provide `pageSizeOptions` to let users switch between page sizes. For server-side pagination supply `totalRows` and `onPageChange`.

## With selection

Enable `selectable={true}` to add row checkboxes. Nothing is rendered by default - pass a `bulkActions` array to expose actions, each fully under your control (`id`, `label`, `icon`, `color`, `variant`, `disabled`). Each action's `onClick` receives the full array of selected row objects.

Set `type: 'split-button'` (default is `'button'`) to render a primary action plus a dropdown of secondary `options`, instead of a plain button. Omit `label` on a `'button'` action to render an icon-only button.

## Row actions menu

Give a column `type: 'actions'` and an `actions` array to render a "more" (⋮) trigger instead of a data value - clicking it opens a menu built from that array (`label`, `icon`, `onClick(row, index)`, and optionally `disabled` - a boolean or a `(row) => boolean` predicate, `danger` for destructive styling, and `divider` to place a separator directly above that item). Only one column may set `type: 'actions'`; it's always rendered at the far right in table mode regardless of its position in `columns`, and top-right of the card in card view (see below). The trigger icon defaults to a vertical 3-dot icon, overridable via `actionsIcon`.

> **Note**: there's no `onRowDelete` prop - deleting a row (or any other destructive action) is just an `actions` entry whose `onClick` updates your own data/state, same as any other action.

<Canvas of={DataGridStories.RowActionsMenu} />

For menu capabilities `actions` can't express - nested submenus, custom `component` content, or keyboard `shortcut` labels - set `renderActions: (row, index) => MenuItemType[]` on the same column instead of `actions` (it takes precedence when both are set). `MenuItemType` is the exact type the standalone `Menu` component takes, so anything `Menu` supports is available here too.

## Responsive card view

Set `hasCardView` to swap the table for a grid of cards once the grid's own measured width (via `ResizeObserver` - not the viewport, so it responds correctly inside a narrow sidebar on an otherwise wide screen) drops to/below `cardViewBreakpoint` (default `640`). Cards themselves lay out responsively with `cardMinWidth` (default `280`) controlling how many fit per row.

Mark one column `cardHeader` and, optionally, another `cardSubheader` to use their values as the card's title/subtitle - every other column renders as a label-above-value field. The row-actions column (see above) always renders top-right of the card, and selection checkboxes top-left, regardless of where either sits in `columns`.

Only the row rendering changes - pagination, filtering, sorting, selection, and inline cell editing all keep working exactly as in table mode. `draggableRows` is not available in card view.

## Expandable rows

Set `expandable` and `renderExpandedContent: (row, index) => ReactNode` to add a chevron that reveals extra per-row content - a dedicated column in table mode, a toolbar toggle in card mode. `renderExpandedContent` is genuinely lazy: it only runs the first time a given row is actually opened, so it's safe to kick off a data fetch from it without worrying about firing for every row up front. The open/close transition mirrors `Accordion`'s own max-height animation for a consistent feel.

By default (`expandMultiple`, default `true`) any number of rows can be open at once; set it to `false` for accordion behaviour, where opening a row auto-collapses whichever other row was open. Use `isRowExpandable: (row) => boolean` to omit the chevron/toggle entirely for rows that shouldn't be expandable. Expansion state works exactly like selection - uncontrolled by default, or controlled via `expandedRows`/`onExpandedRowsChange` (with `defaultExpandedRows` for an uncontrolled initial value).
