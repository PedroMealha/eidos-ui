# MessageComposer

The authoring half of a conversation: an auto-growing text field, optional attachments and a submit control. `Chat` and `CommentThread` both use it internally - reach for it directly only when you are building your own message list and want the same input behaviour.

## Usage

```tsx
import { MessageComposer } from 'eidos-ui';

<MessageComposer
  placeholder="Write a message..."
  onSubmit={async (draft) => {
    await api.send(draft.body);
  }}
/>;
```

## Disabled

<Canvas of={MessageComposerStories.Disabled} />

To express _"this user may not post at all"_, don't render a disabled composer - remove it. `Chat` and `CommentThread` do this via `readOnly`. A permanently disabled field is worse than no field, because it invites an attempt that can never succeed.

## Submitting

`onSubmit` receives a `MessageDraft`:

```ts
interface MessageDraft {
  body: string; // trimmed
  attachments: File[];
  parentId?: string; // set when `parentId` was passed
}
```

Return a promise and the composer handles the pending state for you: the submit button spins, the field locks, the draft clears on resolve - and **is preserved if the promise rejects**, so a failed send never discards what someone typed. A synchronous handler clears immediately.

Errors are not surfaced by the composer; it deliberately swallows the rejection so a keystroke can't produce an unhandled rejection. Report the failure however your app does, with a `Snackbar` or an `Alert`.

## Replies

`parentId` is attached to the emitted draft, and `replyingTo` shows a dismissible hint naming the author being answered. With `onCancel` supplied the hint carries a dismiss control.

<Canvas of={MessageComposerStories.ReplyingTo} />

`autoFocus` is available for this case specifically: the field appears in direct response to someone pressing Reply, so moving focus there is expected. It is off by default.

## Keyboard submission

`sendOnEnter` is off by default, because a comment is usually multi-line and submitted deliberately. Turn it on for a chat-style field: Enter submits, Shift+Enter inserts a newline, and IME composition is left alone so committing a character never sends the message.

## Attachments

`allowAttachments` adds the attach control. Selected files arrive on the draft as `File` objects - uploading them is your app's job, the composer never makes a request. Pair it with `requireBody={false}` to allow an attachment-only message.
