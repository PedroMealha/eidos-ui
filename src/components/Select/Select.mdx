# Select

Dropdown selection control that supports single and multi-select, per-option icons, disabled options, and a clearable state. Use it wherever a native `<select>` element is too limited.

## Usage

```tsx
import { Select } from 'eidos-ui';

const options = [
  { id: '1', label: 'Apple', value: 'apple' },
  { id: '2', label: 'Banana', value: 'banana' },
  { id: '3', label: 'Cherry', value: 'cherry' },
];

<Select options={options} placeholder="Select a fruit..." />;
```

## Labelling

`label` renders a real `<label>` bound to the field, the same as [Input](?path=/docs/forms-input--docs), `Checkbox`, `Radio` and `Textarea`:

```tsx
<Select label="Fruit" options={options} />
```

Where the design genuinely has no room for a visible label - a compact toolbar, a filter row - give it an invisible one instead:

```tsx
<Select inputProps={{ 'aria-label': 'Filter column' }} options={options} />
```

One of the two is required. A `placeholder` is **not** a label: it disappears as soon as something is chosen, so the control becomes anonymous exactly when it has a value worth reading. `Select` logs a development warning if it ends up with no accessible name, and it checks the rendered field rather than its own props - so naming it from the outside, with a wrapping `<label>` or a `<label for>`, counts.

## Keyboard

`Select` is a **select-only** combobox - the field is not editable - so it follows that ARIA pattern rather than [Combobox](?path=/docs/forms-combobox--docs)'s.

| Key                     | Action                                                  |
| ----------------------- | ------------------------------------------------------- |
| `ArrowDown` / `ArrowUp` | Open the listbox, or move to the next / previous option |
| `Enter` / `Space`       | Open the listbox, or commit the active option           |
| `Home` / `End`          | Move to the first / last option                         |
| `Escape`                | Close the listbox, keeping focus on the field           |

Focus stays on the field the whole time: the active option is advertised with `aria-activedescendant` rather than being focused itself, so a selection never moves focus away.

The one deliberate difference from `Combobox` is that focusing a `Select` does **not** open it. `Combobox` opens on focus because its list filters as you type, so seeing it immediately is useful. A `Select` opening on focus would pop a listbox over whatever follows it every time a keyboard user tabbed through a form.

## Multiple select

Set `multiple` to allow picking more than one option. The trigger shows selected labels comma-joined; once more than 2 options are selected it switches to a compact `"N selected"` label so the field stays readable. This is a plain-text label, not removable chips - to deselect, reopen the dropdown and toggle an option off (or use the clear button to reset).
