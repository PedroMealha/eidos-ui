# Menu

Dropdown action list anchored to a trigger element. Items support icons, keyboard shortcuts, dividers, nested submenus, and arbitrary React content via `component` items.

> **Note**: The exported `Menu` component is the wrapper (`MenuWrapperProps`) that accepts a `trigger` and `items` - not the internal `MenuProps` type.

## Usage

```tsx
import { Menu, Button } from 'eidos-ui';
import { User, Settings, LogOut } from 'lucide-react';

<Menu
  trigger={<Button variant="outlined">Open Menu</Button>}
  items={[
    { type: 'item', id: '1', label: 'Profile', icon: User, onClick: () => {} },
    { type: 'item', id: '2', label: 'Settings', icon: Settings, onClick: () => {} },
    { type: 'separator', id: 'sep' },
    { type: 'item', id: '3', label: 'Logout', icon: LogOut, onClick: () => {} },
  ]}
/>;
```

## Keyboard

The menu is a **single tab stop**; arrow keys move between items inside it. Focus enters the menu when it opens and returns to the trigger when it closes.

| Key                | Action                                                 |
| ------------------ | ------------------------------------------------------ |
| `Enter` / `Space`  | Open from the trigger, or activate the focused item    |
| `ArrowDown` / `Up` | Move to the next / previous item, wrapping at the ends |
| `Home` / `End`     | Move to the first / last item                          |
| `ArrowRight`       | Open the focused submenu and move focus into it        |
| `Escape`           | Close the menu                                         |

Disabled items are skipped rather than being dead stops, and separators are never focused. `component` items are not part of the arrow sequence - whatever you render inside one keeps its own focus behaviour and its own keys, so a text field in a menu still works normally.
