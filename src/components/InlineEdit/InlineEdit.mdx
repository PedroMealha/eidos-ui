# InlineEdit

Click (or double-click) a value to edit it in place. Supports uncontrolled and fully controlled editing modes, custom display rendering, and flexible commit/cancel behaviour.

## Usage

```tsx
import { InlineEdit } from 'eidos-ui';
import { useState } from 'react';

function PageHeader() {
  const [title, setTitle] = useState('Untitled page');

  return (
    <InlineEdit value={title} onChange={setTitle} onConfirm={setTitle} placeholder="Add a title…" />
  );
}
```

## Playground

> **Note - Uncontrolled vs controlled editing mode.** By default, `InlineEdit` manages its own open/close toggle internally (uncontrolled). To take external ownership of when editing is active, pass the `editing` boolean prop and respond to changes via `onEditingChange`. This is useful when a parent button, cell-click handler, or keyboard shortcut should drive the edit state independently of the component's built-in trigger. See the [Controlled](#controlled) story below for a working example.

## Controlled

Pass `editing` and `onEditingChange` to take ownership of the open/close lifecycle. The "Edit" button below demonstrates toggling the editing state programmatically from outside the component.

> **Note - `confirmOnBlur={false}`.** Set this to `false` when the parent already owns the commit/cancel lifecycle. The canonical example is a DataGrid: the grid intercepts Tab and click-outside at the container level to commit or discard the active cell editor. With `confirmOnBlur={true}` (the default), blurring the input when the user tabs to the next cell would fire a double-commit - once from the blur handler and once from the grid's Tab interceptor. Setting `confirmOnBlur={false}` hands all commit decisions back to the parent and prevents this.

## Custom display

Use `renderDisplay` to replace the default text rendering with any React node. Custom typography, coloured badges, and icon decorations are all possible while the standard keyboard and commit/cancel flow remains intact.

## Trigger

`trigger="click"` opens edit mode on a single click (default). `trigger="doubleClick"` requires a double-click, which avoids conflicts when the surrounding UI also handles single-click (e.g. selecting a row or following a link).

<Canvas of={InlineEditStories.Trigger} />

## With callbacks

`onConfirm` fires with the committed value when the user presses Enter or blurs the input (subject to `confirmOnBlur`). `onCancel` fires when the user presses Esc and the value reverts to what it was when editing began.

## With placeholder

When `value` is an empty string, the component renders the `placeholder` in a dimmed style. The same text is forwarded to the underlying `<Input>` while in edit mode so the user always has context.
