# DatePicker

A calendar-based date/time input supporting single date, date range, and multiple-date selection. Built on dayjs - values are always ISO strings, making them safe to store and serialise without timezone surprises.

> **Note**: `DatePicker` is generic over the selection `mode`. The `value` and `onChange` types are inferred from the `mode` prop, so always pass the mode explicitly to get accurate TypeScript types.

## Usage

```tsx
import { DatePicker } from 'eidos-ui';
import type { DateTimeValue } from 'eidos-ui';

function BookingForm() {
  const [value, setValue] = useState<DateTimeValue<'range'>>({
    date: { start: null, end: null },
  });

  return (
    <DatePicker
      mode="range"
      value={value}
      onChange={setValue}
      placeholder="Select check-in → check-out..."
      minDate="2024-01-01"
    />
  );
}
```

## Single date

The most common mode - the user picks one date and receives an ISO string value.

## Date range

`mode="range"` lets the user pick a start and end date. The value shape changes to `{ date: { start: string | null, end: string | null } }`.

<Canvas of={DatePickerStories.DateRange} />

## Multiple selection

`mode="multiple"` lets the user pick any number of individual dates. The value is `{ date: string[] }`.

<Canvas of={DatePickerStories.MultipleSelection} />

## With time

Pass `time={{ enabled: true }}` to show an hour/minute picker below the calendar. Add `includeSeconds: true` to expose a seconds field as well.

<Canvas of={DatePickerStories.WithTime} />

## Date range with time

Time selection works with `mode="range"` too - the value gains `time: { start: TimeValue, end: TimeValue }`.

<Canvas of={DatePickerStories.DateRangeWithTime} />

## Date constraints

Restrict the selectable range with `minDate` and `maxDate` (ISO strings). Days outside the range are visually disabled in the calendar and cannot be selected.

<Canvas of={DatePickerStories.DateConstraints} />

## Independent calendars

By default a single month/year control drives every visible calendar, and the others follow a consecutive month apart - rather than each showing its own control that looks editable but is not.

Set `calendar={{ independent: true }}` to give each calendar its own control. They stay clamped so one can never reach or cross its neighbour's month, which would otherwise let you select a range whose end precedes its start.
