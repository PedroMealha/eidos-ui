# Navigation

Sidebar navigation rail combining a brand mark (a custom logo or an initials avatar), a list of items, an optional footer slot, and a built-in collapse/expand toggle. Typically rendered in `PageLayout`'s reserved navigation region, but usable on its own.

> **Note**: `Navigation` has no routing knowledge - `active` and `onClick` on each `NavigationItem` are fully controlled by the consumer. Compute `active: currentPath === item.path` (or however your app tracks the current page) before passing `items` in.

## Usage

```tsx
import { Navigation } from 'eidos-ui';
import { LayoutDashboard, Settings } from 'lucide-react';

<Navigation
  brand={{ name: 'Acme', onClick: () => navigate('/') }}
  items={[
    {
      id: 'dashboard',
      label: 'Dashboard',
      icon: LayoutDashboard,
      active: true,
      onClick: () => navigate('/dashboard'),
    },
    { id: 'settings', label: 'Settings', icon: Settings, onClick: () => navigate('/settings') },
  ]}
/>;
```

Inside `PageLayout`, pass the same shape via the `navigation` prop:

```tsx
<PageLayout navigation={{ brand: { name: 'Acme' }, items: [...] }}>...</PageLayout>
```

## Brand logo

`brand` is a discriminated union - pass exactly one of `name` (renders an initials `Avatar` + text) or `logo` (rendered alone, no separate text), never both:

```tsx
// Initials avatar + name text
<Navigation brand={{ name: 'Acme' }} items={items} />

// A real image instead - no separate `name` text alongside it, since a logo
// typically already bakes the brand name into the image. `alt` is required,
// since there's no other text for it to fall back to.
<Navigation brand={{ logo: { src: '/acme-logo.svg', alt: 'Acme' } }} items={items} />

// Type error - `name` and `logo` can't both be passed, same as `copyright`/
// `component` on `Footer`
<Navigation brand={{ name: 'Acme', logo: { src: '/acme-logo.svg', alt: 'Acme' } }} items={items} />
```

`logo` accepts a real image (svg, png, or jpg), rendered at a fixed height with its aspect ratio always preserved - a vertical, horizontal, or square logo all render correctly, with no distortion or cropping, in both the expanded and collapsed rail. This is deliberately plain, responsive CSS with no JavaScript sizing/measurement at all: a fixed `height`, `width: auto` (derived from the image's own intrinsic ratio), `max-width: min(72px, 100%)` so it's capped at `72px` when there's room but always shrinks to fit whatever's actually available otherwise (the collapsed rail is only ~48px wide), and `object-fit: contain` so it's letterboxed rather than distorted if that ever clamps it below its natural width.

## Collapsing to icon-only

A toggle button collapses `Navigation` to a narrow, icon-only width (`--navigation-collapsed-width`, `64px` by default). It floats half in, half out of the rail's right edge rather than sitting in its own row - a dedicated row reserved space in the layout even when there were too few items (or too short a viewport) to need it, leaving a large, pointless gap above it. While collapsed:

- Every item's label moves into a `Tooltip` (shown on hover) instead of being rendered inline, and its icon is centered.
- `brand.name`'s text (when that variant is used) and the `footer` slot are hidden - arbitrary footer content can't reliably adapt to an icon-only width.
- The brand mark (a `logo` or the initials `Avatar`) stays visible and centered.

The item list also scrolls internally (rather than overflowing the rail) if there are more items than a short viewport has room for - the brand mark, footer, and toggle stay fixed in place above/below it.

The simplest form needs no state at all:

```tsx
<Navigation brand={{ name: 'Acme' }} items={items} />
```

Set `defaultCollapsed` to start collapsed while remaining uncontrolled, or pass `collapsed` (+ `onCollapsedChange`) for full external control - e.g. to persist the preference:

```tsx
const [collapsed, setCollapsed] = useState(false);

<Navigation
  brand={{ name: 'Acme' }}
  items={items}
  collapsed={collapsed}
  onCollapsedChange={setCollapsed}
/>;
```

Pass `collapsible={false}` to hide the built-in toggle button entirely - useful if collapsing should only ever be driven externally.

## Responsive breakpoint

`collapseBelow` is on by default (`768`px): `Navigation` automatically collapses (and re-expands) whenever the viewport crosses that width, in pixels - no extra state or resize listener of your own required. Pass a different value to change the breakpoint, or `collapseBelow={0}` to opt out entirely (no viewport is ever narrower than `0px`):

```tsx
<Navigation brand={{ name: 'Acme' }} items={items} collapseBelow={1024} />
```

This uses `window.matchMedia` internally, so it does nothing until mounted client-side (SSR-safe), and it works the same way whether `Navigation` is controlled or not:

- **Uncontrolled** (the example above): it drives `Navigation`'s own internal state directly.
- **Controlled**: it calls `onCollapsedChange` at the crossing point, exactly as if the built-in toggle button had been clicked - your own state stays in charge either way.

```tsx
const [collapsed, setCollapsed] = useState(false);

<Navigation
  brand={{ name: 'Acme' }}
  items={items}
  collapsed={collapsed}
  onCollapsedChange={setCollapsed}
  collapseBelow={1024}
/>;
```

`matchMedia`'s `change` event only fires exactly at the crossing point, not on every resize tick, so a manual toggle in between crossings (e.g. expanding back while the viewport is still narrower than the breakpoint) is left alone until it crosses again.

## Default

Without `brand.logo`, the brand mark falls back to an initials `Avatar` built from `brand.name`. Click the toggle button at the bottom of the rail to collapse it - `Navigation` manages this itself.
